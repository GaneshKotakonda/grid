## Feature 1: Historical vulnerability

Add an offline, aggregation-only script and a small data helper. The script reads the existing summary, validates unique scenarios and single-line initiating outages, and writes a separate `results/line_vulnerability.json`. It never imports or calls model training or simulation functions. It does not overwrite original outputs. It logs source coverage and skipped/invalid rows. Missing source or invalid required fields produces a clear error; the server can still run without an artifact.

For each line, retain:
- Scenario count.
- Average secondary failed lines (`total_failed_lines - initiating_outage_count`).
- Average cascade length.
- Average load served percentage using only finite known outcomes, plus the contributing count.
- Known load loss percentage (`100 - load_served_percent`) averaged over those same known outcomes.
- TOTAL_BLACKOUT, STABLE, and NON_CONVERGED frequencies as distinct recorded statuses; preserve other statuses as counts if encountered.

NON_CONVERGED is not relabeled as blackout, and missing load metrics are not filled with zero or 100. Trip counts from non-converged runs describe recorded trips and may be incomplete; flag them rather than treating them as complete cascades. Means with fewer than all three defined load outcomes use differing profile subsets and are labeled provisional. Across the current artifact, 34/45 load outcomes are defined. The artifact records source path, source checksum, profile settings, total included/excluded counts, metric definitions, and the fact that no new scenarios were simulated.

Ranking is transparent: descending TOTAL_BLACKOUT frequency, then average secondary failures, then known mean load loss, with ties explicitly identified. A line identifier can order tied entries but must not imply a severity difference. No learned or weighted vulnerability score is introduced.

GET `/vulnerability-data` only reads and validates the precomputed artifact. It performs no aggregation, simulation, model loading, or training. Return a structured unavailable state when missing; invalid artifacts produce a clear error. Missing line observations remain unranked and neutral.

Add `/vulnerability` to the existing Research navigation and SPA document handling. The page uses the current `/grid` bus coordinates and connectivity in a distinct heatmap SVG, leaving the per-run topology/GCN panel untouched. Title: "Historical N-1 Contingency Vulnerability"; subtitle: "Severity observed when each line is used as the initiating outage."

The topology colors lines by a named empirical metric, default TOTAL_BLACKOUT frequency, with a visible percentage legend. A visible uncertainty marker identifies lines with non-converged outcomes, so green does not imply validated safety. Frequencies describe this three-profile history, not real-world probabilities. NON_CONVERGED frequency and secondary-failure information remain visible in line details. Do not reuse the GCN risk legend or label empirical frequencies as model predictions. Color thresholds or a continuous color mapping must be documented visibly; they are display bins, not a hidden severity formula. Show a ranked adjacent list with line IDs, buses, sample counts, rates, secondary failures, cascade length, and known load served. Click or keyboard-select a line or ranking entry to inspect details. State the small historical sample and that nominal/stressed/severe settings differ from the currently selected live scenario. Show a neutral missing-artifact message and keep the rest of the website operational.
